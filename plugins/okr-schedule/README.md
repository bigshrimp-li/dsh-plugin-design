# 个人日常助手（目标日程插件）

DSH 插件，包名和客户端 ID 保持 `@local/okr-schedule`，Loader ID 保持 `okr-schedule`。3.0.0 引入文字链路，3.0.1 修复桌面接入，3.1.0 接入 Bot 执行轨迹；插件将旧目标日程工具接到按空间隔离的 SQLite，并接入真实工作台、受控空间工具、方案版本、Bot 主子会话和综合群协作。本轮仅支持文字输入。

## 3.2.0 日历与创造模式

1. 从 DSH 侧栏进入「目标日程」，首页显示当地当月。勾选目标筛选月、周、日视图，点目标名称进入空间。点一件事项查看或修订本次执行。旧空间可在「记录与 Bot 工作台」检查、备份并显式迁移。
2. 点「创建空间」或已有目标的「调整目标」，用对话或表单编辑同一份草稿。暂离可续编。点「确定创建」或「确定应用」后，目标、K/R、首批安排、展示方式和专属规则一起生效。同名目标按独立标识保存。
3. 在空间内按状态查看 K，填写或请助手起草对应的 R，核对后保存。手动标记实现与记录执行分别生效。可预览事项筛选、分组、统计和排版，按需保存。记账空间按发生月、币种分列收入与支出，点金额可核对明细。
4. 日程助手读取可见目标的正式安排，空间助手读取当前 O。点答复下的引用可查看原事项。模型不可用时仍可手工编排、记录和导出。
5. 在「空间资料」分别导出空间概览、助手规则。通过日历或目标卡删除时，先选定一个正式空间并核对范围，再点「确认删除整个空间」。若索引或文件清理失败，可从首页继续清理同一空间。

每个正式 O 仍使用 `~/.dsh_okr/<O_ID>/space.sqlite`。目录中的 `空间概览.md` 和 `AGENTS.md` 从已提交的记录生成。未确认的创造草稿保存在当前 DSH 窗口来源的浏览器存储中，清除该来源的站点数据会丢失暂存草稿。全局助手会话保存在独立的群存储，单空间会话只保存在所属 O 的 SQLite。原型的固定日期、演示数据、动线标注和重置按钮供离线走查。实现和验收见[本次迭代记录](docs/2026-11-05-calendar-creation-mode/spec.md)。

## 既有工作台能力与验证记录

- 页面、CLI 和 Bot 使用同一领域服务。完整记录直接保存；缺项保留待整理；不支持的类型不产生业务记录。查询和统计明确日期、单位、空值及遗漏数量。
- 行动、排期和实际执行分别保存。日历支持 daily、weekly、monthly 周期投影；投影不产生执行事实。归档后普通事实只读，R 可以继续追评，恢复不自动启用旧排期。
- 空间方案先草稿、实际试用和审查，再按确切版本启用。真实试用由用户选择转入，演示样例不能转正式。方案恢复不回退事项、聊天或记忆；历史批量修改单独确认。
- 每个 Bot 有持久主会话，每个对话任务有独立子会话。同 Bot 默认最多两个子任务并行，同一子任务串行。支持引用续接、重启对账、取消、冷却、休眠、上下文分段和可改删记忆。
- 综合空间只有一个群。成员接收授权原文片段，结果和补充回原群；群来源任务不复用含私聊历史的子会话。查询和规划委托不具备记录权限。
- 安装会话可视化插件后，可从 Bot 标题、工作记录、消息、失败提示及已有真实关联的事项进入执行轨迹。页面连接原任务、投递尝试、会话段、工具回执与发布；返回工作台保留空间、页面与未发送草稿。没有关联的旧记录禁用跳转，不猜配任务。
- 私聊和综合群入口仅显示原来源；混合主会话只展示来源投影。用户明确进入“只读诊断总览”并选择 Bot 后，才能读取该 Bot 完整主会话。查看不启动、恢复或唤醒 Agent，不重放业务操作，不自动生成摘要。旧历史未记录的尝试与用量显示未知。

真实 DSH 的 AgentLoop、持久化、scoped tools、guard、父子关系、受控并行和 SQLite Worker 已使用临时 profile 验证；该检查使用合成模型传输。3.0.1 阶段自动化测试为 74/74 通过，根检查、根测试、宿主检查和浏览器检查（1/1）通过，分发包为 24 个文件，无禁止分发材料。3.1.0 的新增验证和实机结论持续记录在同一份迭代 spec。

3.1.0 的 87 项自动化、工作台浏览器 2 项、ASV Host 13 项／UI 5 项／浏览器 1 项及隔离宿主检查通过。最终已通过根安装器安装到 desktop 并完整重启 DSH：实际历史任务、保存回执定位、来源隔离、群成员任务、诊断主会话、返回草稿及真实新查询轨迹均通过。查看前后业务与运行状态不变。旧 Host 历史缺口仍显示未记录，详细审计见同一份迭代 spec。

本轮不实现图片上传或图像分析。周期日历投影不代表系统已提供后台提醒通知。长对话初始预算采用可配置字符预算，需要真实模型评测后再确定 token 与性能指标。

## 安装与运行

前提：Node.js **≥22.19.0**、npm、已安装 DSH，且 `dsh` 在 PATH 中。新存储只在独立 Worker 中导入 `node:sqlite`；运行能力不足时不迁移数据，也不另建 JSON 事实库。

1. 在仓库根执行 `npm ci`。
2. 执行 `./install.sh --plugin okr-schedule --profile desktop`。安装器先构建和备份，再切换路径，保留其他插件配置。
3. 完全退出并重新打开 DSH，从“目标日程”侧栏进入。导航 slot 和 key 保持不变。
4. 使用旧 O 时，先查看升级检查和备份，再明确执行该 O 的迁移。迁移期间停止其他进程中的旧版写入；不要同时运行两个版本写同一旧空间。

Bot 使用 DSH 已注册的 Agent factory 与模型服务。每次创建或恢复时读取宿主当前默认模型；插件行可通过 `agentOptions` 显式指定 DSH 的 `provider`、`model` 等公开模型选项，显式值优先；不在插件或空间文件里复制 API Key。未配置可用模型时不产生模拟回答。安装插件不自动迁移用户数据。

Bot Trace 同时需要 ASV 1.1.0 或更新版本。在根目录执行 `./install.sh --plugin okr-schedule --plugin agent-session-visualizer --profile desktop` 后完全重启 DSH。ASV 的 3789 端口若属于另一个服务，会明确拒绝新源；不向该进程交付 Bot 凭据。只读授权只在内存保存，过期后从原入口重新授权。

## 数据存储与兼容

数据根目录继续为 `~/.dsh_okr/`。

| 位置 | 用途 |
|---|---|
| `global_index.json` | 旧目录索引；迁移后的权威元数据在所属空间数据库。 |
| `<O_ID>/space.sqlite` 及其 WAL/SHM | 空间、O/K/R、事项、类型历史、分类、排期、执行、待整理、操作回执、方案指针，以及 Bot/任务/记忆的权威状态。 |
| `<O_ID>/bundles/<version>/` | 已确认的不可变方案文件、清单与哈希。 |
| `<O_ID>/migrations/<migration_id>/` | 旧 JSON 的原文备份、SHA-256 和迁移清单。 |
| `<O_ID>/空间概览.md`、`<O_ID>/AGENTS.md` | 从 SQLite 生成的概览与已确认助手规则。可在空间资料中分别重新导出。 |
| `groups/calendar-assistant/group.sqlite` | 日程助手的全局会话。单空间助手的会话保存在所属 O 的数据库中。 |
| `groups/calendar-index/group.sqlite` | 记录待清理的 O。删除完成后只保留稳定 O 标识及完成标记，供迟到请求与重试核对。 |
| `groups/general/group.sqlite` | 综合群的消息、分片、投递和发布关系，不存第二份正式事项。 |
| DSH 自己的会话存储 | 主子 Agent 日志，与空间业务事实分开。 |
| 旧 `meta.json`、`schedules.json` 等 | 未迁移 O 的旧存储；迁移后禁止继续写入，只保留原文。 |

新建目录使用 0700，新 SQLite 与方案文件使用 0600。自动化测试使用临时 HOME 和合成数据；实际 desktop 验收只在独立合成 O 中操作，并只读核对旧文件哈希。业务数据、缓存、凭据和截图不进入 Git 或分发包。

迁移按 O 检查、锁定、备份、写入 staging 库、核对、原子切换；重复执行返回同一迁移结果。旧 O 不变为新建草稿。保留 O/K/R、日程 ID、原值和未知字段；旧打卡只承接已有信息，不推断以往每次周期执行。新库接收写入后，不能直接切回旧 JSON。程序回退需要能读取新库的兼容版本。

原工具名保持不变：

| 工具 | 当前行为 |
|---|---|
| `okr_schedule_query` | 指定 O 时同时限制读取和返回的 O/K/日程；省略日期按空间时区取今天；全日期须显式 `all_dates=true`。 |
| `okr_schedule_checkin` | 归档、歧义 ID、无法定位的周期执行拒绝写入；迁移后保存独立执行记录。 |
| `okr_inspiration_capture` | 仅在对应 O 实际支持灵感类型时保存，返回真实事项 ID。 |

## CLI 与调用边界

`okr-space --help` 列出工具发现、说明、运行和操作查询命令。业务输入使用标准输入 JSON，命令回执在 stdout 输出一个 JSON，诊断使用 stderr。`kind` 区分 `saved`、`pending`、`unsupported`、`trial`、`read`、`accepted`、`conflict` 和失败；退出码 0 不等于已经保存正式事项。

Host 通过继承文件描述符 `OKR_CONTEXT_FD` 交接本机端点和调用凭据；凭据不放命令行或普通环境变量。空间 ID 仅用于定位，不能授予权限。页面使用同样的版本、权限和事务检查，不需要为每次操作启动 CLI。

工具程序只允许有界 JSON 操作，不执行生成的 JavaScript、任意 SQL、shell 或文件系统代码。空间 Skill 随已确认方案发现，不安装到全局 skills 目录。网页写入口验证 Host/Origin、方法、大小、调用凭据与方案版本；确认只能从用户审查入口发起。

## 开发与验收

在本插件目录运行：

```sh
npm run check
npm test
npm run test:host
npm run test:host:browser
npm run test:browser
node ../../scripts/install-profile-probe.mjs
npm pack --dry-run
node scripts/preview.mjs --help
```

`npm test` 包含合成数据、真实 SQLite Worker、HTTP 和 CLI 检查，HTTP 测试需要允许监听本机临时端口。`test:host` 使用已安装 DSH 的真实模块和合成模型传输。`test:browser` 使用本机 Chrome/Chromium 和临时预览服务；可以通过 `CHROME_PATH` 指定浏览器。`DSH_ELECTRON`、`DSH_INSTALL_ROOT` 可指定宿主探测位置。

在本插件目录执行 `node scripts/preview.mjs --calendar`，打开终端给出的本机地址，就能用当天的英语、阅读和记账合成空间手动走查。点记账月卡可以核对 150 元支出和 6,000 元收入。

预览服务器只创建可清理的临时 HOME，提供明确标注的合成数据，不读取用户空间，不伪造 Bot。默认截图随测试清理；需要人工查看时可用 `OKR_BROWSER_SCREENSHOTS` 指定临时输出目录。浏览器、宿主、真实模型和本机业务数据检查分别报告。

`test:host:browser` 在隔离 DSH Web profile 安装插件，使用真实侧栏验证进入、返回、缩放及创建后的重进。需要核对实际模型时，从源码目录运行 `node scripts/calendar-model-probe.mjs`。该脚本仅向已配置的模型发送合成输入，临时 HOME 存放本次数据和会话。

根目录还需运行 `npm run check` 和 `npm test`。可复现的安装探测通过根 `install.sh` 在临时 profile 中验证独立安装、重复安装、插件共存和备份回执，不修改 desktop profile。

## 目录与设计依据

`index.js` 保留插件和旧工具入口；`client.js` 是真实工作台；`src/host/` 包含兼容、Worker、领域、工具、方案、规划、Bot、群与 HTTP 服务；`bin/` 是 CLI；`scripts/` 是源码检查、临时预览和实机探测；`test/` 保存合成测试。

整体产品设计只维护 [Learning 产品设计](../../../learning/原型设计/目标日程插件/产品设计.md)。新需求设计与原型在对应 Learning 需求目录；旧工作台实现见[个人日常助手迭代记录](docs/2026-10-27-personal-assistant/spec.md)，新版日历与空间见[日历与创造模式迭代记录](docs/2026-11-05-calendar-creation-mode/spec.md)。来源快照与历史哈希保留在 `provenance/`，不随实现重算。
