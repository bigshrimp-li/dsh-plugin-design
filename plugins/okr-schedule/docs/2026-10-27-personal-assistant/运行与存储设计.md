## 运行结构

~~~mermaid
flowchart TD
    Global[综合空间群聊] --> Router[群聊派发：成员与任务]
    Router --> Bot[空间 Bot 信箱与任务调度]
    Direct[O 空间私聊] --> Bot
    Bot --> Main[主 Agent：任务工具分配]
    Main --> Child[独立任务子 Agent]
    Child --> Gate
    Page[空间页面与表单] --> Gate[Host 请求校验]
    Cli[工具 CLI] --> Gate
    Legacy[原有三个工具适配器] --> Gate
    Gate --> Scheme[空间方案与版本服务]
    Gate --> Runner[受限工具解释器]
    Runner --> Records[事项与领域服务]
    Runner --> AI[DSH 模型适配器]
    Records --> Store[当前 O 的 SQLite 与附件]
    Scheme --> Bundle[JSON 方案与 Markdown Skill]
    AI --> Candidate[分析结果与来源]
    Candidate --> Runner
    Records --> Receipt[真实回执与页面刷新]
~~~

群聊由 GroupDispatcher 选择成员与任务，私聊由 DirectDispatcher 固定发给当前 O 的 Bot。页面和 CLI 同样使用 Host 绑定。两种派发方式不改变业务数据归属；空间名称不构成记录许可，能否记录取决于当前版本实际支持的类型与工具。

| 模块 | 职责 | 建议代码位置 |
|---|---|---|

Host 入口继续使用 index.js，按能力接入 tools、agents、llm、webServer 和 sessionPersistence；新增服务缺失时给出对应能力状态，避免只因 Bot 服务不可用就阻断原有只读功能。CLI 通过本插件 package.json 的 bin 声明分发，新增依赖只在本插件声明，并同步根 package-lock.json，不复制宿主内部包实例。

## 数据归属与存储

### 权威来源

每个 O 的 space.sqlite 是该空间业务事实与运行状态的权威来源。已确认方案的文件内容不可变，数据库只记录其版本、哈希和启用指针。Markdown 用于 Skill、工具说明和正文导出；正文如果已保存在 SQLite 的 body_md 字段中，导出的 MD 不成为第二个可独立修改的来源。

~~~text
~/.dsh_okr/
  global_index.json                 空间目录索引，不保存各空间业务事实
  groups/<group_id>/
    group.sqlite                    群消息、成员、任务轮次、委托与结果引用
    attachments/                    本群输入的图片，按任务授权成员读取
  <O_ID>/
    space.sqlite                    正式事实、待整理、草稿试用与运行状态
    bundles/<version>/
      manifest.json                 方案清单、版本与文件哈希
      types.json                    事项类型及字段规则
      page.json                     页面与操作绑定
      tools/<tool_id>/
        cli.json                    命令、输入输出与权限声明
        program.json                受限工具程序
        SKILL.md                    当前空间的调用指南
        review.md                   面向用户的能力说明
    attachments/<attachment_id>     图片原件及有来源关系的派生图片
    migrations/<migration_id>/      迁移清单及旧 JSON 备份
    meta.json、keypoints.json 等      未迁移时仍为旧存储；迁移后保留只读
~~~

global_index.json 是可重建目录投影。迁移后的 O 元数据以 space.sqlite 为准，索引不接受工具直接修改。group.sqlite 是本群消息与协作状态的权威来源，不保存第二份正式事项。各 Bot 信箱保存授权片段与 group_message_id，DSH 主会话记录路由投影，子会话记录各任务实际接纳的材料与执行历史；这些投影不提供第二个群消息编辑入口。私聊原始消息以 Bot 信箱为准，任务输出按来源通道发布，不将混合 session 日志直接作为某个聊天的界面历史。分片与附件交接不能因为断线而丢失，也不能被其他群或私聊默认读取。综合空间没有替代 O 的业务数据库。

SQLite 的 WAL、SHM 等事务辅助文件留在所属目录。业务与配置文件使用 SQLite、JSON、Markdown；图片是已确认的附件例外。DSH 自己管理的会话日志不迁成空间业务文件，也不作为事项的权威来源。

### 核心表

| 数据组 | 主要字段 | 约束 |
|---|---|---|
| space | objective_id、title、purpose、lifecycle、archived_at、active_bundle_id、revision | 每库仅一个 O；lifecycle 为 draft 或 formal，归档独立表示 |
| dimensions | id、objective_id、名称、原有状态、archived_at | K 只能属于本 O；不拿 K 代替分类 |
| bundles / drafts | id、base_bundle_id、hash、状态、兼容性报告、确认凭据 | 已确认版本不可改写；调整草稿不替换正式指针 |
| items | id、type_id、type_version、main_k_id、title、fields_json、body_md、source_id、revision、created_at | 每条正式事项属于本库 O 和一个类型；主 K 可空，存在时必须在本 O |
| item_changes | item_id、前后 revision、变更字段、来源、operation_id | 保留已执行修改依据；不是新增撤销产品入口 |
| category_tables / category_versions | 表标识、分类标识、版本、父分类、名称、有效状态 | 分类 ID 稳定；旧事项保留旧引用及当时含义，合并不静默重写历史 |
| item_actions / schedules | item_id、行动状态、排期种类、时区、重复规则、启用状态 | 行动能力与时间均可选；取消排期不删除事项 |
| executions | id、item_id、occurrence_key、实际时间、状态、心得 | 单次和每次周期执行各自保存；相同 occurrence_key 的重试不重复打卡 |
| results / result_evidence | R 标识、主要评价对象、正文、关联 item_id | R 的主对象是本 O 或本 O 的 K；归档后仍可追评 |
| sources / attachments | 来源消息、附件标识、哈希、实际格式、归属、关联对象 | 只关联本空间已授权的内容；不接受任意磁盘路径 |
| pending_materials / trial_records | 原始输入引用、已匹配类型、缺项、候选内容、草稿版本、provenance | 不出现在正式统计；演示来源与真实来源由 Host 标记 |
| operations / jobs | 请求键、输入哈希、状态、结果引用、版本、取消和错误信息 | 支持断线查询与重试；模型输出不能自行声明操作已成功 |
| bots / bot_runtime | bot_id、main_session_id、路由水位、上下文代次、调度租约 | 每个 O 一个持久主会话；主循环串行，任务执行独立 |
| bot_messages / task_messages / inbox_outbox | message_id、收发方向、来源范围、片段引用、回复关系、序号、投递与接纳水位、幂等键、输入哈希 | 先入箱再投递；状态更新与出箱同事务；至少一次投递，消费与业务写入分别去重 |
| dialogue_tasks / task_checkpoints | 目标、材料范围、交付、完成条件、phase、residency、wait、source_scope、revision、last_relevant_at、unrelated_turns、检查点引用 | 任务不是事项；超时只改变驻留；delivered 可续接，closed 后续新建关联任务 |
| task_runtimes / task_runs | task_id、child_session_id、parent_session_id、创建意图键、run_id、执行租约、接纳游标、回执引用 | 一个任务一个可恢复子会话；同一子会话串行；创建中断先对账，不能重复启动 |
| context_baselines / context_segments | agent/session、SP/UP 版本、冻结检查点、来源水位、保留轮次引用、memory revision 依赖、上下文代次 | 主子分别段内追加；压缩只在安全边界换段；不把任务切换当作主会话历史替换 |
| memories / memory_revisions / memory_tombstones | 长期条目或任务经历、O、可见范围、来源、有效期、revision、删除水位 | 事实以事项为准；改删触发上下文失效，旧来源不自动复活 |
| memory_review_jobs / memory_cursors | 来源范围、原任务子会话、已审阅位置、幂等键、提取结果、失败状态 | 当前子 Agent 提交候选；维护事件回原任务；无独立记忆 Agent 要求，失败不撤销业务保存 |

数据库启用外键和唯一约束。类型定义以已确认 bundle 内的 JSON 为准；类型索引和全文检索表是派生数据，可以重建。旧事项保留创建或最近明确修改时的 type_version，新规则只约束新事项及明确发生的修改，不批量补造旧字段。

fields_json 承载按类型定义的业务字段，Host 按对应版本校验类型、必填项、引用与范围。常用筛选字段可建立受控索引；工具不提交任意 SQL，不执行 ATTACH、不加载 SQLite 扩展，也不直接打开数据库路径。

类型字段使用稳定 field_id，并声明显示名称、kind、是否必填、单位、约束和分类引用。首版覆盖文本、布尔、整数、定点小数、日期、时间点、分类、事项引用和图片引用；需要列表时显式声明。定点小数以十进制值及精度表达，避免将需要精确汇总的值隐式转成二进制浮点数。改显示名称不改变字段身份，改字段含义或类型则生成新版本并检查兼容性。

### 群协作数据

| 数据组 | 主要内容 | 关键约束 |
|---|---|---|
| groups / members | 综合群、协调成员、空间成员、成员状态与版本 | 首版一个综合群；成员权限与 O 状态重新校验 |
| group_messages | 顺序、发言者、正文、来源事件、关联任务、可见范围 | 群消息唯一；来源事件重放不重复发布 |
| group_tasks / task_parts | 用户请求、任务依赖、fact_key、目标 O、允许动作、状态 | 同一事实只分配一个 O；模型不能扩大原请求权限 |
| deliveries / member_cursors | 投递标识、目标 Bot 信箱、消息水位、接收回执 | 重投复用同一标识；没有接收回执不能提前推进水位 |
| result_publications | O 的 operation_id、目标群任务、待发布内容与发布回执 | 业务已保存而群发布失败时补发，不重做业务写入 |
| coordinator_runtime | 协调 Bot 信箱、主 session、协调任务子 session、群任务和状态水位 | 没有所属 O 的协调 Bot 不能因此读取全部 O |

空间成员的信箱、任务、主 session 与子 session 绑定登记在所属 O，群库记录委托关系和对应 Bot/任务引用。一个群协作任务可分为多个成员对话任务，不混用两类任务的标识和完成条件。读群上下文、读 O 事实和发布群结果分别经过受控接口；不为便利而让工具直接打开两个数据库。群聊任务和私聊任务同时修改一条事项时，由 O 的事务和 revision 处理冲突。

### 时间与统计

created_at 表示保存时间；发生日期属于可选业务字段；排期属于可选行动能力。三者不能互相默认替代。日期字段区分日历日期与带时区时间点，禁止自动为只有日期的记录补造午夜时间。

每份统计声明事项类型、筛选范围、采用的日期字段、时区、分组粒度、单位和空值处理。年、季、月、周、日只是可选粒度，不预装成所有空间的固定功能。缺少统计日期的事项保留在全部记录中，并单独返回未纳入数量。

全局日历只汇总明确启用排期的行动。仅日期进入当日区域，时间点用于提醒，有起止时间才显示时段。普通资料或训练事实即使有发生日期，也不自动进入日历。

### SQLite 运行条件

推荐使用内部 SqliteDriver 适配 node:sqlite，在专用工作线程中执行数据库操作，避免同步查询阻塞 Host。拟将新版插件的最低 Node 版本提高到 22.19.0，并在启动时检查所需事务、JSON 查询和全文检索能力。设计基线2.3.0声明 Node >=20；当前3.0.0已升级为Node >=22.19.0，这项运行要求是兼容性变化，实施时必须更新清单和安装说明，不能只因开发机使用 Node 26 就默认宿主满足。

本机 Node 26.8.1 已确认能导入 DatabaseSync。本机 DSH 应用为 0.2.1-rc.3，使用其 Electron Node 24.21.0 以 Node 模式启动独立进程，内存数据库的外键、JSON 查询、FTS5 与事务回滚探测通过；没有访问用户数据库。这证明本机应用所带运行时具备基础 SQLite 能力，仍需验证真实插件 profile 中的工作线程、生命周期和打包运行。

其他目标宿主不满足时，先保留旧插件运行，不创建新空间、不开始数据迁移；需要继续支持 Node 20 时，应单独选择并验证 SQLite 驱动，不能静默改用另一份 JSON 事实库。node:sqlite 的引入历史见 [Node 官方说明](https://nodejs.org/api/sqlite.html)。

## 空间方案与生效流程

### AI 的交付物

| 交付内容 | 用户默认看到 | 内部校验 |
|---|---|---|
| 使用说明 | 能记录什么、如何输入、会看到什么、哪些情况不能处理 | 能力说明与可执行命令一致 |
| 页面方案 | 可试用的内容区、筛选、查询、记录入口 | 组件、查询和命令引用存在；没有虚构指标 |
| 记录规则 | 字段含义、必填项、分类与日期处理 | 类型版本、字段标识和历史兼容性 |
| 工具能力 | 输入、输出、写入影响、示例与失败反馈 | CLI schema、受限程序和权限声明一致 |
| 空间 Skill | 可展开查看的使用指南 | 只绑定本空间、当前版本及已声明命令 |
| 试用与影响说明 | 真实试用结果、演示标识、版本差异、受影响历史范围 | 试用回执来自运行器；新增权限和不兼容项可定位 |

AI 不自行给出“已测试通过”状态。Host 运行合成样例和边界用例，产出实际结果。审查页默认展示使用能力，数据结构、CLI 和 Skill 放在可展开详情中。

### 创建、调整与恢复

1. 用户创建 O，Host 分配稳定空间和 Bot 身份，lifecycle=draft，active_bundle_id 为空。用户需求进入该 Bot，不先生成正式事项。
2. AI 根据需求生成候选 bundle。Host 校验引用、字段、权限、程序和页面，并在草稿范围运行样例。校验失败仍是草稿。
3. 用户通过对话调整。对“修改一条内容”与“修改记录规则”有歧义时先追问。打开调整预览后，当前页面携带 draft_id；用户仍使用同一对话入口，无需切换技术模式。
4. 用户确认当前草稿。Host 校验草稿 revision、bundle 哈希、兼容性报告和真实试用选择。确认绑定具体版本；确认后又改动的内容必须重新审查。
5. Host 准备不可变 bundle 文件，校验文件哈希后，以数据库事务切换 active_bundle_id、登记确认凭据并将首次空间设为 formal。失败时维持原指针，不出现页面、工具和 Skill 各用不同版本的状态。
6. 后续调整使用 base_bundle_id 和乐观并发控制。正式版本继续工作；过期草稿先重算差异。首版同一空间只维护一个可编辑调整草稿，避免相互覆盖。
7. 恢复旧方案时，以旧版本内容生成新的调整草稿，重新做当前数据兼容性检查。确认后生成新的版本号，不回退事项、聊天、Bot 身份或记忆。

方案激活前暂停该空间的新写请求，等待已进入提交阶段的写入结束。长时间模型分析不占数据库事务；分析结果回来时重新核对版本。旧版本结果不能越过切换继续写入；状态回到待核对或按新版本重新校验，不能丢失用户输入或盲目重跑已经成功的操作。

### 试用与正式数据

草稿试用与正式调用使用不同执行范围。试用中的所有写入进入 trial_records，不允许正式事项写权限；读取正式数据时只取得本空间的只读快照。AI 生成的演示数据由 Host 标记 demo，模型不能把演示数据改标为真实。

确认方案和转入事项分别返回结果。方案先完成原子激活，再按用户选定的完整真实记录生成可恢复的转入任务；选择清单与确认一并持久化。每条转入以 trial_record_id 去重，在单个事务内创建事项和转入回执。断线后继续未完成部分，不重新创建已成功事项。

缺项、未选中或转入失败的真实材料保留待整理；演示数据永不转入。已知不支持的记录请求遵守最新规则，不创建试用业务材料作为变相兜底；用户的普通对话历史仍可保留。开始创建时描述空间需求属于设计对话，不按记录失败处理。

### 历史数据与归档

新增必填字段、改分类、改变统计口径或删除页面模块，不修改旧事项。旧类型版本与分类版本保留；新页面对不能解释的旧值标明历史版本，或提供只读详情，不能擅自转换。

批量修改通过独立变更计划执行：列出命中事项及 revision、变更前后示例、总数和计划哈希。用户确认该计划后才提交；实际执行前再次校验全部目标版本，有冲突则重新预览。首版按空间单事务执行受限批量，超出规模拆成明确批次；数据库 schema 升级与业务历史改写分别管理。

O/K 归档后，普通事项与配置禁止写入，R 追评保留入口。已支持的新增内容进入待整理并说明封存原因，不能借待整理直接改变封存事实；没有合适类型的内容仍是不记录。恢复归档不自动启用旧周期提醒。工具停用或页面移除保留事项、附件与历史方案。

## 工具、CLI 与空间 Skill

### 受限工具程序

首版工具程序为有类型的 JSON 操作序列，不执行模型生成的源代码字符串。程序可以声明输入字段、条件分支、查询、分组、数值计算、图文分析、候选记录和输出投影。表达式使用有限运算符与字段引用，不使用 eval 或 Function；数据不能被解释成程序。

| 操作类别 | 宿主提供的能力 | 运行限制 |
|---|---|---|
| 查询与统计 | 按类型、字段、时间和分类查询；分页、聚合与排序 | 参数化查询；字段与聚合在能力清单中声明 |
| 数据整理 | 字段映射、单位转换、日期解析、有限条件判断 | 不猜填必填信息；缺省值必须来自已确认规则 |
| 事项操作 | 提交新增或修改候选、生成待整理材料、关联来源 | 统一领域服务执行最终校验和事务，程序不能直接落库 |
| 行动与复盘 | 通过专用服务处理排期、执行记录、K 关联和 R | 不开放任意表名、任意 SQL 或覆盖 O/K/R 文件的能力 |
| 模型分析 | 提交指定图片、文本、结果 schema 与任务说明 | Host 选择模型并执行，结果先作为候选 |
| 文件内容 | 读取本空间已授权的 MD/JSON 内容，生成受控导出 | 使用对象标识与相对虚拟路径，不暴露本机路径或文件系统 API |

工具程序先计算结果与待提交操作。Host 完成授权、业务规则与并发校验后再提交；含模型调用的程序不能先写一半事项再等待模型。确定性计算不交给模型重新计算。

初始运行预算建议为每次最多 100 个程序节点、查询默认 50 条且单页不超过 500 条、结构化回执不超过 256 KiB，超过时分页或返回结果引用。禁止无限循环；批量工作由 Host 分页任务执行。具体数值属于实现配置，需要用代表性样例验证，不作为已经测得的性能结论。

确实需要自定义算法时，新增经过测试的宿主操作并发布插件版本，或在后续需求建设独立隔离运行器。不会通过开放通用终端、安装任意依赖或直接使用 Node vm 来绕过首版限制。

### CLI 协议

新增 okr-space 可执行入口。每个空间工具在 cli.json 中声明稳定命令名、说明、输入 schema、输出 schema、读写能力、需要的事项类型及 AI 能力。命令能力清单可被机器读取，帮助与 Skill 从同一声明生成。

~~~text
okr-space tools list --json
okr-space tool describe <tool_id> --json
okr-space tool run <tool_id> <command> --input - --request-id <request_id>
okr-space operation get <operation_id> --json
okr-space --help
~~~

这些是拟新增命令，当前不能执行。业务输入从标准输入读取 JSON；stdout 只输出一个 JSON 回执，诊断信息进入 stderr。退出码建议：0 表示请求正常处理，2 表示输入无效，3 表示作用域或权限拒绝，4 表示版本冲突，5 表示运行失败。待整理、无法记录和已接收分析任务都必须检查 result.kind，不能把退出码 0 解释成事项已保存。

Host 为调用绑定上下文，通过私有 IPC 或继承文件描述符交给 CLI；上下文凭据不出现在模型、命令行参数、环境日志或 Skill 中。O 标识是定位信息，不能凭一个 --space 参数取得授权。用户在终端手工调用时，需要从当前本机空间获得有效调用凭据；普通用户使用页面和对话，无需操作 CLI。

AI 通过唯一的空间工具入口提交 tool_id、command 和业务 input。Host 将这些字段映射到 CLI 协议，并使用同一运行模块执行；可用 execFile 调用已安装的可信 CLI，禁止拼接 shell 命令。页面可直接调用同一模块，不必为了形式再启动子进程。

示例是学习空间保存资料，仅说明协议形状，不是所有空间必有的工具：

~~~json
{
  "requestId": "req_example",
  "toolId": "learning-records",
  "command": "record-material",
  "bundleId": "bundle_example",
  "input": {
    "title": "事务隔离笔记",
    "content": "今天阅读后的要点……"
  }
}
~~~

请求中的 bundleId 只用于检测过期请求。真正的 O、Bot、对话通道、执行范围和可用能力由 Host 的绑定确定。响应统一包含 requestId、operationId、bundleId、kind、data 和 error；kind 使用以下结果：

| kind | 含义 | 可出现的业务对象 |
|---|---|---|
| saved | 已完成数据库提交 | itemId 与 revision |
| pending | 已支持，但缺项、存在歧义或受到归档限制 | materialId、原因与待补字段 |
| unsupported | 当前版本没有合适能力 | 解释原因；没有 itemId、materialId |
| trial | 草稿试用结果 | trialRecordId 与来源标记，不是正式 itemId |
| read | 查询或统计完成 | 数据、范围、口径、遗漏数量与分页信息 |
| accepted | 异步任务已接收 | jobId；不显示“已保存” |
| conflict | 方案或记录版本发生变化 | 当前版本与刷新入口；不覆盖新值 |
| failed / unknown | 确定失败，或外部任务结果尚未确定 | 错误码、可重试性和查询原操作的方法 |

### 写入与重试

Host 在接收输入时生成请求身份；统一入口拆分后使用稳定 part_id，补充信息沿用 material_id。去重依据为本空间内的请求身份、命令和输入哈希。相同请求与相同输入返回已持久化回执；同一请求键却改变输入时返回冲突。相同文本的新用户消息是新意图，不能仅按文本哈希合并。

新增事项、来源关联、操作回执在同一 SQLite 事务提交。图片文件先写入暂存文件并计算哈希，完成受控重命名后再登记引用；数据库失败产生的无引用文件由清理任务回收，不把丢失图片的事项报告为完整成功。

已有事项修改携带 expectedRevision，防止页面与 Bot 相互覆盖。单条明确修改沿用普通事项交互；目标不明先澄清。批量历史变更必须引用已确认的计划，工具程序不能生成自己的“用户已确认”标记。

### Skill 生效范围

Skill 与对应工具、CLI 和程序一起绑定 bundle 哈希。发现列表仅包含当前 O；加载正文时核对工具 ID 和版本。首版不把生成的 Skill 安装到 DSH 全局 skills 目录，也不把每空间文件登记进根 plugins.json 的全局 skills 清单。

创建或恢复运行会话时，Host 在 Agent setup 阶段组合当前空间提示词、受控工具和执行 guard。Skill 是使用指南，不能授予文件、模型、网络或跨空间权限。类型缺项、不支持、草稿和归档分支同时由 Host 服务执行，不能只写进 Skill。

## 对话与派发接口

群聊、私聊、上下文装配与 DSH 会话映射以[技术方案](技术方案.md)为准。综合空间采用群聊派发，O 空间采用私聊派发；同一个 Bot 的两类输入进入同一信箱，由持久主 Agent 通过任务工具创建或续接独立子 Agent。主会话保留路由历史，子会话保留各任务执行历史；不把全量信箱或父历史直接复制给子 Agent。

Host 同时校验业务归属与对话归属。业务归属决定可访问哪个 O；对话归属决定从哪个群聊或私聊取上下文、向哪里发布结果。群聊任务不自动获得私聊原文和私聊记忆；用户明确引用的材料按授权范围提供。群内任务的业务事实保存到所属 O，群内结果与追问按任务绑定回到原群；用户可以打开私有空间查看或继续处理相同事项。

旧的“统一入口交接后必须跳入私聊”不再作为唯一流程。群聊委托、群内发言顺序、来源分片、确认凭据、取消与重试都由 GroupDispatcher 和宿主登记，具体映射见主文档。

## 页面、图片与模型分析

### 页面生成与调用

综合空间使用群聊框架，展示参与成员、任务状态与群内消息；O 私有空间的固定框架承载导航、状态、私聊、待整理、工具审查、版本和确认入口。AI 的 page.json 只描述内容区及工具面板，可使用摘要、表格、列表、趋势、分类统计、Markdown 内容、表单与行动视图，并声明查询、筛选、列字段和命令绑定。

布局可以由 AI 调整，但用户没有组件库、拖拽、排序按钮或布局设置面板。图表只读取工具返回的数据；隐藏模块不删除底层记录。组件不是“财务总览”等固定业务对象，学习空间可以展示资料和阅读进展，运动空间可以展示训练和体测。

客户端只渲染通过校验的配置，不直接运行 AI 生成的 HTML/JavaScript。Markdown 禁止原始脚本和危险 URL；图片由附件服务按授权引用提供。新组件超出渲染器能力时明确提示需要插件扩展，不能显示一个不能调用的假按钮。

建议提供 /okr-space/api 和受控事件接口。API 覆盖空间列表与状态、方案草稿与审查、确认与恢复、工具调用、操作查询、Bot 消息、附件、待整理和记忆。所有写请求具备请求键、版本和 Host 签发的调用凭据；确认方案与批量历史变更由用户操作入口产生独立确认凭据，生成工具无权签发。

网页访问检查方法、请求大小、Host/Origin、宿主窗口身份及调用凭据，不能只以“localhost”判定可信。页面状态在数据库提交后刷新；先显示处理中，拿到 saved 回执后才显示已保存。网络超时通过 operationId 查询状态，不直接换请求键重试。空状态、加载失败和存储损坏分别展示。

### 图片与 AI 任务

图片通过上传接口流式写入暂存区，验证实际格式、大小、像素上限和内容哈希。模型与工具只接收 attachment_id；文件名、原始路径和模型输出不能决定落盘位置。空间附件只能由本空间读取，跨空间复制或裁剪必须经过统一入口的明确分片规则。

AI 分析通过 DshAiAdapter 调用当前 Bot 关联的模型配置，不暴露 API Key，也不存在自行假设的 session.ai()。分析请求固定 O、Bot/session、bundle、工具、输入哈希、图片引用、任务说明和输出 schema，只传本次分析必要内容。后台结果通过信箱回到原 task_id，不进入当时恰好活跃的其他任务。

模型分析使用独立的有界 LLM 调用。不能向正在等待工具返回的同一主 Bot 再投递任务并等待其完成。请求可取消，状态从 queued、running 到 succeeded、failed、cancelled 或 unknown；外部调用成功与正式事项保存分别记录。

模型返回值先经过 schema 校验，保留模型身份、分析时间、来源、假设、缺项和用户修正。估算值与实测值通过字段语义区分；不统一要求用户批准所有图片结果。若当前类型允许估算且输入完整、意图明确，可按规则保存；关键假设未解决时进入待整理。用户后来修正时保留原分析与修正来源。

模型不支持图片时，返回可理解原因并允许补充文字或选择可用模型；不自动扩大权限或悄悄改用外部服务。分析超时只重试分析阶段，不能重复创建已经提交的事项。

## 隔离与执行校验

Host 维护不可由模型改写的调用绑定：objective_id、bot_id、channel_kind、conversation_id、main_session_id、child_session_id、agent_role、task_id、context_generation、bundle_id、执行范围（正式或草稿）、tool_id、command、request_id、授权操作和到期时间。主会话可能处理不同来源，子会话固定任务与来源。权限不得只由父子关系、session_id 或当前界面选中的任务推断。绑定来自空间入口与服务内部登记。每次查询、模型调用、附件读取、写入和结果投影都重新校验绑定。

| 边界 | 实施方式 |
|---|---|
| 空间目录 | Host 根据已登记 O 定位目录，校验真实路径、拒绝符号链接逃逸；工具拿不到任意路径接口 |
| Agent 工具 | setup 中限制继承的全局工具，并通过 guard 对执行名称和调用身份作正向校验；恢复会话重复配置 |
| 通用能力 | 空间 Bot 不开放通用终端、文件读取、网络、其他 O 的业务工具或任意子 Agent；仅主 Agent 可通过 task 工具创建受控子 Agent，群内可提交受限委托，私聊不暴露跨 Bot 派发；PTC 不能成为旁路 |
| Skill | 仅按当前 O 与 bundle 加载；旧对话中的 Skill 文本不能赋予新权限 |
| 业务写入 | Host 检查类型、完整性、归档、版本、确认凭据和幂等键；JSON 程序不能自行提交数据库事务 |
| 模型上下文 | 图像分析只接收所需材料；群任务只接收授权引用；混合来源主会话的自由文本不直接对群发布，不能把路由摘要当读取权限 |
| 返回结果 | 数据、附件、错误详情与日志都做当前范围投影，拒绝通过错误信息泄露其他 O 内容 |
| 未知宿主能力 | 缺少 guard、Agent setup 或模型接口时关闭对应新能力，保留可用只读入口，不退回无限制执行 |

本地 [DSH 沙箱声明](../../../../node_modules/@deepseek-ai/dsh-sandbox/lib/types/index.d.ts)说明 workspace-write 主要控制文件写入效果，网络与进程可见性不在该词汇范围。仅设置 cwd 或环境变量不能隔离读取。这也是首版选择受限解释器、不给生成工具文件系统和进程能力的原因。

隔离目标是插件内的 Bot、工具和页面只能通过授权接口访问本空间。操作系统账户所有者直接查看自己的本地文件不属于插件可阻止的行为；需要抵御宿主进程失陷时，应另行增加操作系统或容器边界，不能用本方案的作用域校验代替。

## 旧数据迁移与兼容

### 迁移流程

旧数据不会因打开页面自动批量改写。迁移与用户的方案审查是不同操作；先提供只读检查结果和备份信息，再按选定 O 执行技术迁移。现有 O 已是用户使用中的领域，不因升级被重新变成待确认的新建 O；迁移后生成只承接原有能力的兼容方案，新能力仍走调整草稿。

1. 停止该 O 的旧 JSON 写入并取得迁移锁，校验目录、文件可读性、ID 唯一性、K/R 引用与归档状态。失败仅阻止该 O，不能返回全空数据掩盖问题。
2. 保存原始 JSON 文件及哈希，创建 staging 数据库。使用确定性映射保留 O/K/R 和旧日程 ID；名称、期限、正文、分类和来源尽量原样承接。
3. 日程迁为启用行动能力的事项；灵感和资料迁为对应类型；R 保持独立评价对象。旧状态和 checkin_note 作为一份历史执行信息保留，不能推断过去每次重复行动的完成情况。
4. 校验记录数量、关键字段、关联、日期语义和归档状态；生成迁移报告。未知扩展字段保留在 legacy_payload，不静默丢弃或编造含义。
5. 完成数据库写入和校验后原子安装正式库，登记 storage_version。更新全局索引投影；旧 JSON 转为只读备份，由兼容适配器读取新库，不再双写。
6. 失败时未切换的 O 继续读旧 JSON。已切换但索引刷新失败时，以 O 内完成标记修复索引。迁移过程可重入，不生成第二份相同事项。

新库开始接收写入后，禁止直接切回旧 JSON，否则会丢失迁移后的事实。运行程序回退必须使用能读新库的兼容版本；需要恢复数据备份时先核对新增数据，单独生成恢复计划。空间方案恢复同样不回退数据库事实。

### 原有工具承接

三个旧工具名称保留，内部改为调用领域服务。空间 Bot 中旧工具只能绑定当前 O，输入的 objective_id 不一致即拒绝；不能让兼容入口绕过新规则。

全局旧查询继续服务整合视图，但由可信全局入口明确范围。查询指定 O 时 O/K/日程全部过滤，未指定 date 按空间时区解释为今天；需要全量查询时增加明确参数。写操作按目标对象解析 O 并执行当前规则；ID 不唯一时返回歧义，不能选第一个命中对象。

旧打卡增加可选 occurrence_key 或日期。单次行动可以直接定位；周期行动无法唯一确定某次执行时要求补充，不能沿用覆盖整条周期状态的行为。灵感工具只在当前版本实际有对应类型时保存，不把灵感类型变成所有无法匹配内容的兜底。未迁移空间先补齐路径、锁、归档与回执校验，再继续旧存储写入。

## 实施顺序与验收

建议先打通可信数据与调用链，再建设生成能力。以下每步都形成可以单独验证的结果；具体任务状态在[迭代记录](spec.md)维护。

1. **验证宿主适配。** 使用合成空间验证 Agent create/resume、工具 guard、主子会话创建、续接、来源隔离与恢复、图片模型调用、Web API 和 node:sqlite。确认新版 Node 要求及分发方式；未通过不启用新运行链。
2. **统一数据访问。** 建设空间存储、领域服务、真实回执、旧工具适配与只读迁移检查。先解决当前跨空间返回、归档绕过和虚假成功反馈。
3. **实现工具协议。** 提供可执行 CLI、受限程序解释器、schema 校验、幂等提交、图片附件和异步任务。使用人工编写的两个通用能力样例检验协议，再让 AI 生成同格式程序。
4. **实现空间方案。** 接通首次草稿、调整草稿、确认激活、真实试用选择转入、历史版本恢复和独立批量变更计划。
5. **实现群聊与私聊。** 完成两种派发器、Bot 信箱与任务调度、主 Agent 路由和任务子 Agent 执行、记忆生成与召回、上下文预算和恢复；同一私聊入口处理日常使用与设计意图。
6. **接通页面与统一入口。** 用真实 Host 数据替换 initialData，接入方案渲染、工具审查、待整理和群聊成员派发与任务分片。本轮 HTML 已提供交互验证材料，仍须以真实 Host 数据重新验收。
7. **验证迁移与安装。** 在临时 HOME 和目标 DSH 测试 profile 中运行迁移、中断恢复、打包、独立安装与插件共存；通过后再安排真实数据迁移和上线。

| 验收场景 | 必须观察到的结果 |
|---|---|
| 学习空间输入受支持的完整资料 | 直接保存一次；重载后存在；页面与 Bot 返回同一 itemId；没有撤销入口 |
| 已支持类型缺少必填信息 | 只有待整理材料；补齐后一次性转正式，不重复事项 |
| 学习空间输入不支持的训练记录 | 解释原因；不转交、不提示切换；无事项、待整理和业务附件副作用 |
| 空间实际支持训练类型 | 即使空间名称是“学习”，仍按该能力处理，不能仅按话题拒绝 |
| 创建与调整草稿 | 只有用户确认的版本启用；原正式版本在调整期间可用；演示不能转正式 |
| 试用选择转入后断连 | 方案状态明确；已成功记录不重跑，未成功记录仍可恢复 |
| 新增必填项、重分类、恢复旧方案 | 旧值原样保留；批量修改无独立确认不能执行；旧 Bot 与记忆不回退 |
| 同一条事项被两个入口同时修改 | 只有匹配 revision 的写入成功，过期写返回冲突 |
| O/K 归档与恢复 | 普通事实封存；支持的新输入待整理；R 可追评；提醒不自动重启 |
| 群聊多空间输入部分成功 | 各成员只收到本任务必要内容；状态独立；群内回报；只重试失败且可重试的部分 |
| 主子会话切换、压缩与重启 | Bot 主 session 保持；各 task 恢复原 child session；主子独立换段；来源正确、无重复写入、无权限扩大 |
| 学习讲解、追问、笔记与独立计划 | 前三者连续工作，计划独立；闭环后新建关联任务，第二种等指代可追溯 |
| 状态计时与冷却 | 30 分钟或 8 轮等初始阈值只调驻留；等待与交付状态不被伪装为完成 |
| 记忆增量生成、召回、修改与删除 | 提取有来源，检索先过滤权限；事实回查；删除使已加载工作上下文失效；重试不重复写记忆 |
| 删除记忆后再次检索旧聊天 | 后续请求不注入旧记忆，不因自动整理恢复该偏好 |
| 修改 O 参数、附件 ID、路径或调用旧工具 | Host 拒绝越界，返回值和错误中不含其他空间数据 |
| 图片识别失败或模型不支持图片 | 反馈实际状态，不显示分析完成，不编造字段或重复保存 |
| 旧 JSON 损坏与迁移中断 | 故障定位到具体空间；可恢复；不丢记录、不伪造分次执行历史 |

测试需同时验证“出现的正确结果”和“不应产生的副作用”。真实模型样例用于检验语义路由与缺项判断，确定性集成测试用于验证存储、权限和重试；两者不能相互替代。性能验收先采集大空间查询、长对话检索和图片分析数据，再确定指标，不在文档中虚构延迟保证。

## 实施前的技术验证项

以下属于工程验证，不重新询问已确认的产品规则。

- **DSH 生命周期。** 本地接口声明可用，但实际 profile 的 Agent factory、父子会话投递、检查点换段、会话释放和持久化行为还未验证；DS-Bot 的压缩包装不能直接照搬。
- **运行版本。** 本机 DSH 自带 Node 的内存数据库探测已通过；继续验证真实插件 profile 的工作线程和安装包，并确认从 Node >=20 提高到 >=22.19.0 的发布影响。
- **工具表达能力。** 用学习资料和运动记录覆盖真实需求，确认受限程序足以表达首版能力。任意脚本运行需要独立方案，不暗中开放。
- **上下文与图像。** 验证实际模型窗口、图片限制、取消和错误回执；未满足时只关闭相应能力，不声称已经支持。
- **前端接入。** 当前旧 slot 与本地 DSH 客户端接口的兼容性需实机验证；现有 HTML 的模拟文案不计为运行证据。

这些门禁通过后，才能将相应开发任务标记为可上线。本技术方案完成、产品定稿、原型调整、数据迁移和功能验收各自记录，不合并成一个“已完成”状态。
