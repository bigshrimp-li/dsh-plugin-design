# T01：按目标保存 OKR、事项与已确认配置

**状态：** 已完成　｜　**依赖：** 无，可直接开始

**PRD 依据：** [总览：空间文件与正式记录](../../../../../../learning/原型设计/目标日程插件/需求/2026-11-04-日程页与创造模式/产品设计.md#空间文件与正式记录)；[总览：过程目标的状态与反馈](../../../../../../learning/原型设计/目标日程插件/需求/2026-11-04-日程页与创造模式/产品设计.md#过程目标的状态与反馈)；[助手：数据放在哪里](../../../../../../learning/原型设计/目标日程插件/需求/2026-11-04-日程页与创造模式/AI助手对话与数据读取.md#数据放在哪里)

为其余 tickets 提供同一套按 O（目标）读写的领域操作。在已有 SQLite Worker 上扩展记录与版本检查。现有 `results` 允许同一对象有多条成果，事项也带可选的 K；不能假设旧记录已满足新约束。

**改动入口：** [domain.js](../../../src/host/domain.js)、[storage-worker.js](../../../src/host/storage-worker.js)、[compatibility.js](../../../src/host/compatibility.js)、[storage.test.mjs](../../../test/storage.test.mjs)。

## 验收条件

- [x] 正式空间使用稳定 O 标识和 `~/.dsh_okr/<O_ID>/space.sqlite`。同名两空间分别读写；改名不换目录。草稿不占正式 O，也不出现在正式查询中。
- [x] 每个 K 保存名称、起止日期、标准和可撤销的手动实现日期。每个 K 恰有一个 R 位置；重复保存同一 R 只能修订，跨 O 引用和失效版本均不能写入。
- [x] 有时间的事项可只绑定 O。计划和执行事实分开，已完成事项保留原标识；一件事项支持多个 K 的复盘取证，日历只计一次。重复日程可定位到一次具体发生。
- [x] 每个 O 的默认筛选、分组、统计口径、事项区样式、已确认助手规则均能按版本读回。SQLite 是正式来源；旧 bundle 布局和 Markdown 不与之双写为权威配置。新的问答链路以 OKR 和事项为业务记忆。
- [x] 用合成旧空间演练升级：保留 O、事项 ID、执行历史及原始备份；缺期限、未配对或一 K 多条历史 R 须报告，不能猜日期或静默删除、覆盖历史。旧空间按现有显式迁移入口处理；既有三个兼容工具仍可用。

**验证方式：** 在临时数据根目录创建两个同名 O，验证隔离、重复请求、重启读回、迁移前后记录和备份；不对用户已有空间做迁移。

## 实施与验证

在插件目录运行 `node --test test/calendar-storage.test.mjs test/storage.test.mjs`。两个独立 Worker 同时确认相同草稿只产生一个 O，同时保存同一个 R 得到一次成功和一次版本冲突。改名保留目录，已完成事项保留原 ID，K 的实现日期和 R 分别修订。周期事项按具体日期读取与完成，全局统计不读取执行正文或金额。

旧 JSON 日程可在日历中只读投影。显式迁移的合成空间包含缺期限的 K、同一 K 的两条成果、未配对的 O 成果与无法定位发生日的旧打卡。原始 JSON 和备份逐份一致，原事项与执行 ID 保留，升级报告列出缺口。既有兼容工具由 `test/host.test.mjs` 与 `test/service.test.mjs` 回归。
