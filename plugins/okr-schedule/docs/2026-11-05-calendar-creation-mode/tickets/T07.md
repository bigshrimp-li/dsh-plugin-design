# T07：按发生月展示记账收支并可逐笔核对

**状态：** 已完成　｜　**依赖：** [T04](T04.md)、[T06](T06.md)

**PRD 依据：** [空间内：用月度账本核对已入账金额](../../../../../../learning/原型设计/目标日程插件/需求/2026-11-04-日程页与创造模式/空间内.md#用月度账本核对已入账金额)；[空间内：记账和账目详情](../../../../../../learning/原型设计/目标日程插件/需求/2026-11-04-日程页与创造模式/空间内.md#记账和账目详情)；[助手：三个空间怎样用同一套读取流程](../../../../../../learning/原型设计/目标日程插件/需求/2026-11-04-日程页与创造模式/AI助手对话与数据读取.md#三个空间怎样用同一套读取流程)

以已完成的记账事项承载实际交易，沿用同一 O 的事项身份、执行详情和视图规则。账本提供实际发生日期、方向、金额、币种、类别和入账状态；计划核账仍是普通日程。

**改动入口：** [client.js](../../../client.js)、[domain.js](../../../src/host/domain.js)、[service.test.mjs](../../../test/service.test.mjs)、[browser.test.mjs](../../../test/browser.test.mjs)。

## 验收条件

- [x] 「记一笔」预填今天、支出、人民币；输入名称、实际日期与时间、方向、正金额，类别缺省为「其他」。金额以元输入，最多两位小数；演示表单示例的上限是九位整数。未来日期、缺名称、时间或金额无效均保留表单并说明，取消不入账。
- [x] 按「确认入账」才新增同一 O 的一件已完成事项。按实际发生自然月、币种分别汇总，收入和支出分列，不默认相抵。计划提醒及缺少合格金额的记录排除并说明；金额空态与完整查询为零应能区分。
- [x] 月份显示币种及已入账笔数；分别展开/收起收入、支出，点击某笔打开原事项。支持按方向筛选、按类别汇总；修订方向、金额或实际情况后点「保存执行记录」，同一事项只重算一次。
- [x] 11 月买菜支出 120 元、交通支出 30 元、工资收入 6,000 元：月卡分别为 150 元和 6,000 元。只看餐饮得 120 元，10 月账目与 11 月提醒不计入；另一币种单列。新建且只有核账计划的空间不出现虚构金额。

**验证方式：** 用合成账目检查跨月、两币种、未来发生日、缺值、取消、改方向与金额，以及从月卡/列表打开同一条明细。

## 实施与验收结果

「记一笔」由当前 O 的记账配置开放。表单校验名称、发生日期、时间、金额与币种，确认后写入同一事项和执行。金额以整数分保存；页面按发生日期、币种和方向分别合计，并标出未计入项。

在插件目录运行 `OKR_BROWSER_TEST=1 node --test test/space.browser.mjs`。Chrome 与临时 SQLite 实测 11 月 CNY 支出 150.00、收入 6,000.00，餐饮筛选显示 120.00，USD 20.00 独立显示。10 月单列，核账提醒不计入。明细可展开、收起并打开原事项，把买菜 120 改成收入 123.45 后再改回支出，原事项仍仅一条且实际情况保留。取消和无效输入不入账。补记 5.67 后总支出 159.12，下载概览可读回新金额。宽窗实际截图已与「记账空间-月度收支.png」核对。
