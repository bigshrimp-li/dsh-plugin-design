## 验收条件

- [x] 首次主动发送后才拟案：产物含一个 O、有标准与起止日期的 K、每 K 唯一待反馈 R、归 O 的首批排期、事项区默认规则及样式、空间专属助手规则。尚无实际结果就展示空态。
- [x] 每轮先读最新草稿；用户在预览里改的字段保留。只更新点名的 K、事项或规则，指出改了哪里。两项听力均可匹配时先用日期/名称询问；关键信息不明一次问一个问题，其余可给可编辑的建议。
- [x] 11 月 5 日输入「四周掌握 120 词、八周听懂日常对话，周六 19:30 学词」生成各自的 K 和 11 月 7/8 日练习。再说「首项改到周六 10:00，按周汇总计划时长」，只改首项和视图，听力安排保留。
- [x] 「按月展示消费和收入」落入事项视图；「以后问收支先列收入」落入可核对的空间规则；「这一次先看收入」不改长期规则。可用字段不足、实际与预估不清时说明或追问，不发明账目、时长或达标情况。
- [x] 输入「确认创建」「直接建」仍只回复核对入口；新建不读其他 O 的正文，调整只引用绑定 O 并区分计划、展示、规则的前后差异。生成失败保留原草稿，不以本地假回复代替模型。

**验证方式：** 用英语三轮与记账两种意图做可重放的对话评测，核对变更字段、保留字段和零正式写入；独立报告真实模型能否澄清并生成可编辑方案。

## 实施与验收记录

创造助手接收最新表单与草稿版本。已存在的 K 和事项按标识合并局部修改。多个候选听力事项会列出日期和名称请用户选择。正式创建或应用始终在页面确认；输入「确认创建」显示草稿状态与按钮名称。长期回答规则和事项视图独立审阅。

在插件目录运行 `node scripts/calendar-model-probe.mjs`。真实 Provider 按 2026-11-05 生成两个英语 K 和 11 月 7／8 日两项练习，次轮保留用户手改说明，只改首项为 10:00 与按周合计计划分钟。文字确认无正式写入。另以两条听力事项验明澄清，以已确认空间验明规则调整保留原排期。记账三轮实测分别生成按月收支视图、调整以后问答时的收支顺序、对本次查看保留原长期规则。

模型曾仅用正文描述规则差异，或返回无法解析的 JSON。已按场景收窄输出结构，只应用经 Host 校验的增量；无效 JSON 有一次结构化重试，仍失败则保留草稿并报告服务状态。
