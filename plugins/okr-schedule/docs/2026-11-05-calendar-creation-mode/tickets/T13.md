# T13：仅在按钮确认后创建或更新正式空间

**状态：** 已完成　｜　**依赖：** [T01](T01.md)、[T11](T11.md)

**PRD 依据：** [创造模式：确认前的检查和退出方式](../../../../../../learning/原型设计/目标日程插件/需求/2026-11-04-日程页与创造模式/创造模式.md#确认前的检查和退出方式)；[创造模式：确认后交付什么](../../../../../../learning/原型设计/目标日程插件/需求/2026-11-04-日程页与创造模式/创造模式.md#确认后交付什么)；[总览：各入口怎样读写](../../../../../../learning/原型设计/目标日程插件/需求/2026-11-04-日程页与创造模式/产品设计.md#各入口怎样读写)

从同一份草稿产生一次明确的宿主提交。区分新建、改计划与仅改规则/展示的校验；处理占用提示和并发编辑。客户端只按宿主成功回执进入新空间或刷新原空间，并通知日历和阅读稿更新。

**改动入口：** [scheme.js](../../../src/host/scheme.js)、[domain.js](../../../src/host/domain.js)、[service.js](../../../src/host/service.js)、[client.js](../../../client.js)、[service.test.mjs](../../../test/service.test.mjs)。

## 验收条件

- [x] 新建、增改 K 或改排计划时，校验 O 名称、至少一个 K、每 K 的名称/标准/有效起止日（可同日），并至少保留一件有名称、有效日期和开始时间、正时长的拟排事项。未填完的行不能提交；既有 O 只改助手规则或展示时，无未来待执行事项亦可提交。
- [x] 新排或改期同时检查正式安排及同草稿的其他安排，排除被本次替换的原时段。结束即为下一项开始不算重叠；冲突在预览就地提示，可改时间也可保留重叠提交。避让信息不泄露别的 O 的内容。
- [x] 「确定创建」分配正式 O、初始化独立 SQLite，成套写入 O/K/R、首批日程、默认视图、排版和专属规则；打开新空间，首批日程即使被空间默认筛选隐藏，也在全局可查。「确定应用」修改原 O，改名不新建。
- [x] 提交前复核权限和基线版本：草稿暂离期间若同一规则或布局已改，显示差异，重新核对后才能覆盖。刚完成的事项、已保存 R、手动实现标记保留最新值；重复点击或重试不复制空间、K 或事项。
- [x] 提交失败保留可修正的草稿，不显示成功，也不留下可见的半个空间。提交成功才触发阅读稿刷新（T15 验证两份文件）；不要求用户先在旧版试用界面建立空间。

**验证方式：** 用手工编辑和助手生成的相同形状草稿检查拒绝、同日 K、连续/重叠时段、只改规则、冲突重审、重复点击与故障恢复。对照正式目录及全局查询证明确认前后差异。

## 实施与验证

在插件目录运行 `node --test test/calendar-storage.test.mjs` 和 `OKR_BROWSER_TEST=1 node --test test/space.browser.mjs`。同日 K 可提交，非法日期、零时长与未完成的拟排被拒绝。无未来排期的既有空间可单独改规则。预览显示重叠并允许明确保留，恰好相连的时段通过。浏览器走通手工修改与会话拟案两条入口。

新建在临时目录内完成 SQLite 和两份阅读稿后，整目录一次切换。调整在原 O 的 SQLite 事务中完成。测试在草稿暂离期间改排版、写反馈、手动实现和完成事项，再提交旧草稿，验证冲突重审及保留最新事实。重复确认返回同一 O 与事项。
