## 验收条件

- [x] 按页面已有数据提供只读建议：有 K 可看目标进展；从今天起七个自然日（含今天）内有待执行事项才建议「未来 7 天待执行事项」；有已入账记录的记账空间优先本月收支。实际答复和引用使用同样的范围与状态。提到其他 O 时只引导切换。
- [x] 查进展先读所指 K 的标准、有效期、标记及对应 R。用户要起草时，只取同 O、同期、与标准相关且有执行记录的已完成事项。多个 K 时先选定；证据不足提示补记录或手写。草稿可修改，只有「确认保存反馈」改同一 R，不自动达标。
- [x] 英语复测 20 词、16 词达标，可答本次 80%，不能认定累计掌握 120 词；分清 55 分钟计划、已完成事项的 35 分钟计划和实测用时。跑步答 11 月 3 日实测 4 公里/28 分钟、11 月 7 日计划 32 分钟，并分别引用。
- [x] 记账只筛餐饮（含未确认的当前预览）时，「当前视图花了多少」答 120 元且只引用买菜；「11 月全部支出」重新查全月，答 150 元并引用买菜及交通。只读问答不保存默认、不入账。
- [x] 请求改筛选、聚合或排版时先预览；口径含糊先追问，字段缺失说明限制。纯样式用「应用排版」，混合或规则用「保存为默认」。要求移动或隐藏固定 O/K/R 时，只给可调整的事项区选项。
- [x] 本次复盘偏好只用于本轮；「以后复盘先报收入」显示规则差异，经「在创造模式核对规则 → 确定应用」后下轮才加载。本 O 内新增 K、改排事项引到「调整目标」。会话切换不继承别的 O 的规则、数字或未应用预览。

**验证方式：** 分别用英语、跑步、记账的合成空间走查只读、缺证据、R 起草、预览、规则更新与越界提问；比对实际记录 ID 和写入数量，真实模型语义与合成协议分别记结果。

## 实施与验收记录

单空间每轮重读本 O 已确认的规则与版本。数字使用正式事项、执行和当前筛选计算，币种、计划与实际分别标明。R 草稿需要匹配同 K 期限及类型的执行证据，编辑器确认后才保存。排版预览和长期规则分别交给各自确认入口。

运行 `node scripts/calendar-model-probe.mjs`。真实模型在合成英语空间区分 55 分钟计划、已完成的 35 分钟计划和 80% 单次复测，R 草稿引用实际执行。跑步空间分别引用 4 公里／28 分钟的实测训练和 32 分钟的后续计划。记账当前餐饮是 120 元，仅引用买菜，全月支出是 150 元，引用买菜与交通。跨 O 提问引导切换。

运行 `OKR_BROWSER_TEST=1 node --test test/assistant.browser.mjs`。Chrome 验证了预览放弃后旧按钮失效、核对 R 草稿后手工保存、长期规则在创造模式中确认并对账。过期的配置或执行版本要求用户重新取证。

原生桌面补测发现两处差异，已修复并复验。在保持餐饮筛选的前提下查整月不限类别，返回 150 元及两笔来源；反向查当前视图返回 120 元及一笔来源。有人民币与美元两种账目时，按原币种分列 CNY 150.00 和 USD 10.00，并可回看三笔明细。详见[原生桌面复验](../spec.md#macos-原生桌面复验与本机清理)。
