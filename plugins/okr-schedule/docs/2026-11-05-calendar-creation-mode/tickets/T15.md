# T15：生成并分别导出空间概览和助手规则

**状态：** 已完成　｜　**依赖：** [T07](T07.md)、[T13](T13.md)

**PRD 依据：** [空间内：空间资料与删除](../../../../../../learning/原型设计/目标日程插件/需求/2026-11-04-日程页与创造模式/空间内.md#空间资料与删除)；[总览：空间文件与正式记录](../../../../../../learning/原型设计/目标日程插件/需求/2026-11-04-日程页与创造模式/产品设计.md#空间文件与正式记录)；[助手：数据放在哪里](../../../../../../learning/原型设计/目标日程插件/需求/2026-11-04-日程页与创造模式/AI助手对话与数据读取.md#数据放在哪里)

在用户确认创建后，为该 O 从 SQLite 生成两份 Markdown。在正式记录或已确认规则变化后刷新对应阅读稿。「空间资料」展示目录用途和已确认规则，并提供两个独立下载入口。

**改动入口：** [storage-worker.js](../../../src/host/storage-worker.js)、[domain.js](../../../src/host/domain.js)、[scheme.js](../../../src/host/scheme.js)、[client.js](../../../client.js)、[storage.test.mjs](../../../test/storage.test.mjs)。

## 验收条件

- [x] 在临时数据根目录走一次创建，确认前没有正式目录，成功后同一 `<O_ID>/` 下有 `space.sqlite`、`空间概览.md` 和 `AGENTS.md`；同名 O 不相互覆盖，改名不改变目录。
- [x] 概览包含当前 O 的目标、每个 K 与对应 R、期限、状态、事项与执行结果；账目保留收支方向和金额。规则稿只含这一个 O 已确认的专属规则，不混入宿主通用指令、其他 O 或未确认草稿。
- [x] 用户可以分别「导出空间概览.md」「导出 AGENTS.md」。保存 R、修订账目或确认规则后再导出，得到最新正式内容；未确认编辑不体现在导出中。导出不修改 SQLite，外部改 Markdown 不回写业务事实。
- [x] 写文件失败时不得把旧文件报成最新。业务是否已提交以 SQLite 回执为准，可按正式版本重新生成；再次生成不重复写入之前的业务操作。

**验证方式：** 用两个同名合成 O 检查目录、文件内容及刷新；对比暂存/确认前后两次导出，修改一份外部副本验证不反向导入。

## 实施与验证

在插件目录运行 `node --test test/calendar-storage.test.mjs` 和 `OKR_BROWSER_TEST=1 node --test test/space.browser.mjs`。浏览器分别下载两份 Markdown 并读回，概览含最新执行、修订后的单笔账目与反馈；规则文件逐字等于当前 O 已确认的规则。

把合成空间的概览文件位置替换为不可覆盖的目录，业务回执仍为已保存并附阅读稿刷新提示，导出报告失败。修复目录后重新导出得到最新记录，事项、执行、R 的数量均保持一致。覆盖外部副本后再次导出，内容仍来自 SQLite。
