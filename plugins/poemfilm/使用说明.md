# poemfilm 使用说明

poemfilm 把诗人的自述、原词朗读、分镜和剪辑保存在同一个作品目录里。已有素材可以直接在本机出片。要比较两种表演，可以复制一个版本，共享原画，再给同一段台词选另一条录音。

## 1. 在 DSH 中安装和找到启动器

在仓库根目录运行以下命令。示例选择 `desktop` profile。安装完成后完全退出并重新启动 DSH。准备好 Python 3.11 或以上版本、uv；剪辑和验片还需要 PATH 中的 FFmpeg 和 FFprobe。

```bash
./install.sh --plugin poemfilm --profile desktop
```

宿主将作品绝对路径和版本名分别绑定到插件的 `work` 和 `edition` 后，模型可以调用 `poemfilm_show` 查看台词和镜头。`poemfilm_plan` 检查素材，`poemfilm_verify` 检查成片。若需要模型选入候选和导出，由宿主显式配置 `allowEdit: true`。授权模型生成素材还需绑定一个已签发的 `job`。

用户在终端操作时，把下面的 `desktop` 换成正在使用的 profile。此命令在该 profile 的 bundle 中查找已安装的插件，只需在当前终端运行一次。

```bash
poemfilm_profile_dir="${DSH_HOME:-$HOME/.dsh}/profiles/desktop"
POEMFILM_BIN="$(node -e '
  const fs = require("node:fs"), path = require("node:path");
  const profile = path.resolve(process.argv[1]);
  const pkg = "@local/poemfilm";
  const manifest = JSON.parse(fs.readFileSync(path.join(profile, "package.json"), "utf8"));
  if (!manifest.dsh?.profile?.bundles?.includes(pkg)) throw Error("此 profile 尚未启用 poemfilm");
  const launcher = fs.realpathSync(path.join(profile, "node_modules", pkg, "bin", "poemfilm"));
  fs.accessSync(launcher, fs.constants.X_OK);
  process.stdout.write(launcher);
' "$poemfilm_profile_dir")"
"$POEMFILM_BIN" --help
```

直接从源码体验时，可在仓库根目录设置 `POEMFILM_BIN="$PWD/plugins/poemfilm/bin/poemfilm"`，首次运行 `"$POEMFILM_BIN" --setup` 安装锁定版本的依赖。下文终端命令都使用已定位的启动器。另选一个自己的工作目录存作品素材。

## 2. 新建作品并导入素材

在当前目录准备一份 UTF-8 的 `定风波.txt`，按想一起朗读的段落换行。作品标题和诗人名可自己填写。有角色设定图时，可在初始化命令后加 `--reference ./苏轼.png`，多张图就重复该参数。初始化后，`show` 会列出每段原文的台词 ID。

```bash
"$POEMFILM_BIN" init 我的定风波 --poem ./定风波.txt --title 定风波 --author 苏轼 --edition 温叙
cd 我的定风波
"$POEMFILM_BIN" show --json
```

已有分镜通过 `"$POEMFILM_BIN" import script --file 分镜.json --source 原创 --license 自有` 导入，返回的 `id` 用于 `"$POEMFILM_BIN" select script 候选ID --edition 温叙`。分镜文件的 `lines` 为依次播放的台词，每项包含 `id/kind/text`。原词须保持原 ID、文字和先后顺序。原创自述使用 `kind: narration`。按顺序排列的 `shots` 每项包含 `id/line_id/prompt`。

导入原画和声音使用相应的 `import art`、`import voice`，附上 `--target 镜头或台词ID`、`--file 文件`、`--source 来源`、`--license 使用依据`；再运行 `select art` 或 `select voice`。候选原文件和其他版本继续保留。试听核对后可用 `select voice 候选ID --reviewed` 记录在本版，需要句内时间码时另传 `--cues 文件.json`，条目格式为 `{"start_ms":0,"end_ms":1500,"text":"谁怕？"}`，顶层为数组。

在 `editions/温叙.yaml` 可编辑最终剪辑。下面的镜头共用一条录音，第一镜保留步态，第二镜承接余下声音。所有素材路径相对于作品目录。

```yaml
shots:
  - id: walk
    line_id: line-01
    prompt: 苏轼拄杖走过雨中的竹林
    media: {kind: motion, path: assets/步态.mp4, in_ms: 0}
    duration_ms: 2040
  - id: leaves
    line_id: line-01
    prompt: 竹叶向下弯，积雨滴落
    media: {kind: still, path: assets/竹叶.png}
```


已有第一版素材后，先剪出“温叙”，再复制出“行吟”。给“行吟”选入另一组录音后，对它依次执行相同的排镜、出片和验片命令。

```bash
"$POEMFILM_BIN" plan --edition 温叙
"$POEMFILM_BIN" render --edition 温叙
"$POEMFILM_BIN" verify --edition 温叙
"$POEMFILM_BIN" edition fork 温叙 行吟
```

排镜结果的 `renderable` 为真时即可导出。有素材缺口时，`issues` 会列出镜头和需要补的时长。最终视频在 `build/温叙/master.mp4`，同目录有 SRT、署名和验片报告。报告包含实测时长、帧数、响度与字幕，同时列出待人工核听的字音和待审看的动作。

## 3. 绑定只含赠金的项目

1. 在自己的 API 组织确认订阅赠金已经到账、无其他余额、使用预付方式、关闭自动充值，且其他机器或项目没有绕开此账本的消费。组织的月度预算和项目密钥都不能单独选择某笔赠金。[赠金记录](https://platform.openai.com/settings/organization/billing/credit-grants) · [官方扣费顺序](https://developers.openai.com/api/docs/guides/chatgpt-api-credits)
2. 在自己控制的终端运行下列命令，使用自己的组织 ID 和项目 ID。密钥在隐藏输入框录入，只存 macOS 钥匙串。`auth status` 只检查本机配置。`auth check` 是可选的联网操作，读取模型目录；成功只说明该密钥能读此目录。
3. 将[赠金核对模板](examples/赠金核对模板.json)复制到私有位置，根据实际账单补全金额、核对人与证据、有效时间。金额用美元字符串，例如 `"0.00"`，时间带时区。模板的空值会阻止真实请求。`funding bind` 将本作品与该资金配置关联。核对过期后用新快照更新。

```bash
"$POEMFILM_BIN" auth login --profile poetry-api --org 你的组织ID --project 你的项目ID
"$POEMFILM_BIN" auth status --profile poetry-api --json
"$POEMFILM_BIN" funding bind --profile poetry-api --record /绝对路径/赠金核对.json
"$POEMFILM_BIN" funding status --json
```

CLI 以组织为单位统计多个作品的预留。订阅登录、环境中的通用 API 密钥和第三方图像或语音工具不会接替失败的请求。平台没有按请求锁定指定赠金的公开开关；本地状态是以所有者核对记录、受控组织支出和价格依据做出的准入判断。若账户条件不成立，仍可执行离线工作。

## 4. 生成候选并控制费用

```bash
"$POEMFILM_BIN" generate script --estimate-only --json
"$POEMFILM_BIN" generate script --max-usd 0.50
"$POEMFILM_BIN" select script 返回的候选ID --edition 温叙
"$POEMFILM_BIN" generate art --shot 实际镜头ID --estimate-only --json
"$POEMFILM_BIN" generate voice --line 实际台词ID --delivery '语气平静，在反问前稍稍停顿' --estimate-only --json
```

去掉 `--estimate-only` 并显式传入单次 `--max-usd` 后才可能发送请求。命令中的美元数是预算例子。同一输入优先复用已经生成且通过指纹检查的素材。改变读法或显式指定新的 `--take` 会创建不同候选。请求结果不明则保留预留；不要通过换 take 重新发出可能已经计费的请求。核对异常用量后，由资金所有者用新的核对记录处理。

- **分镜** 使用 Responses API。返回的词句、原文字序和镜头覆盖范围须通过校验。
- **原画** 使用 GPT Image 2 的生成或编辑接口。OpenAI 的公开计算器给出估计费用。目前的严格模式只在已有匹配本次模型、尺寸、质量、输入规模和有效期的厂商计费上界时发送。由所有者在资金核对记录的 `vendor_price_bounds` 登记相应书面依据；估价器结果、随意填写的美元数或作品自身的配置都不能充当上界。没有依据时可导入已有画面。[官方图像计价说明](https://developers.openai.com/api/docs/guides/image-generation#calculating-costs)
- **语音** 使用 Realtime API，保留 WAV 和转写。自动比对通过后，仍可按句核听读音和情绪。估价使用受限模型上下文、最高输出 token 数和标准费率；输出时长随实际演绎变化。

## 5. 给模型绑定版本和委托预算

DSH 的默认工具为 `poemfilm_show`、`poemfilm_plan`、`poemfilm_status`、`poemfilm_estimate` 和 `poemfilm_verify`。宿主配置 `job` 后提供 `poemfilm_job_status` 和 `poemfilm_generate`。配置 `allowEdit: true` 后提供 `poemfilm_select` 和 `poemfilm_render`。例如试读工具接受 `asset: "voice"`、`target: "从 show 获取的台词 ID"`、`delivery: "末字轻轻落下"` 和 `max_usd: "0.20"`。`status` 读取本机账务状态，用户在自己的终端办理登录和资金操作。

独立的 stdio MCP 宿主使用上文解析出的启动器绝对路径作为 `command`，设置 `args` 为 `["--work", "作品绝对路径", "mcp", "--edition", "温叙"]`。其工具名省略 `poemfilm_` 前缀。

需要付费生成时，用户或可信宿主先签发总预算。例如两次演绎共享一份 0.40 美元的任务额度。

```bash
"$POEMFILM_BIN" job authorize --edition 温叙 --scope voice:line-05 --max-generations 2 --max-usd 0.40
"$POEMFILM_BIN" job status --job 返回的任务ID
```

将 `--job 任务ID` 附加到 MCP 启动参数才会暴露该任务的生成工具。需要允许宿主选择候选或导出时，另外加 `--allow-edit`。跨多个镜头的任务可重复传入 `--scope`；例如 `--scope script --scope 'art:*' --scope 'voice:*'` 可授权为该作品的指定版本制作多种素材，共用一个上限。完全开放的 Shell 与用户同等受信；对需要限制的模型仅暴露这个固定作品的 MCP 服务。调用方模型自身的计费由宿主决定。

## 单独使用 Python 版

需要独立 Python CLI 时，在这个插件目录运行 `uv tool install '.[agent]'`，并通过该安装的 CLI 启动。运行离线测试可在插件目录执行 `uv run --extra agent --extra test pytest -q`，媒体测试需要 FFmpeg 和 FFprobe。macOS 钥匙串用于存储生成时使用的 API 密钥。资金核对文件、证据、作品素材与成片保存在自己的私有目录。

## 账务记录的两个可选字段

`vendor_price_bounds` 仅用于已经有供应商书面价格上界的情形。每条记录须给出厂商 `provider=openai`、定价依据 `basis=supplier_guaranteed_per_request`、报价版本 `version`、适用的精确 `model/endpoint/size/quality`、完整请求上界 `upper_usd` 和 `valid_until`。同时记录输入约束 `max_prompt_bytes/max_reference_count/max_reference_pixels/max_reference_bytes`、官方 HTTPS 来源 `source_url`、证据文件 `evidence_file` 与其 `evidence_sha256`。报价记录及证据应保存在作品目录外。系统匹配范围和核对文件指纹，书面文件的真实性由所有者核实。公开单图输出参考价不等于整次调用上界。新建作品默认使用 `image: {size: 2048x1152, quality: high}`，可在作品配置中调整。

`reconciled_operations` 用于在服务端结果不明后对账。先确认后台的实际情况，用更新的账单快照逐项列出 `operation_id`、原预留 `expected_reserved_usd`、`outcome`（`charged`、`not_charged` 或 `not_sent`）、`actual_usd` 和 `evidence_ref`。已计费的结论另须注明 `reflected_in_snapshot`。未核实的请求保留其预留。已成功且金额已体现在新快照中的旧请求，可通过 `accounted_operations` 填入相应 ID，避免重复扣减本地预算。
