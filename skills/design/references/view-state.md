# 用户指的是哪块画板

遇到「这块画板」「我正在看的那个」「这个按钮」「这些」「左边那个界面」，或者其他任何目标取决于**用户屏幕**的说法，动手之前先读这篇。新建设计稿不需要读。

**这个环境里没有设计稿查看器，也没有标注通道**：没有任何工具调用能取到用户正在看什么、选中了什么。所以：

- 用户的话是相对**他们自己**的屏幕说的，而你手上只有磁盘上的文件。
- 目标只有一个可能时，按上下文判断（本次对话刚建的那份设计稿、只有一个 `.dc.html`、只有一处符合描述的元素），并在回复里用一句话说明你改的是哪里。
- 有**两个以上**可能时，问清楚是哪一个再动手。可用的说法：画板的 `title`（没有就用去掉 `.dc.html` 的文件名）+ 元素的类型和开头几个字（「『Spring Menu』那个标题」）。别问「你指的是哪个元素」这种空问题——把你看到的候选列出来让他挑。
- 用户是在看到**渲染结果**之后说的，而你只能读到 markup：涉及视觉判断的说法（「太挤了」「颜色太跳」「字号太小」）按 markup 里对应的样式属性理解（间距、颜色、字号），改那一处。
- 用户改过文件是可能的：改之前**每个文件都当场读一遍**，绝不用记忆里的副本（见 SKILL.md「修改」）。

不要假装看到过渲染结果，也不要为了「确认」去渲染或截图（见 SKILL.md「**除非用户要求，否则绝不验证**」）。
